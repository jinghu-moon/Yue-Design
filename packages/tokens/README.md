# @yue-ui/design-tokens

Yue 的设计 Token，纯 CSS 自定义属性。不依赖 Vue，不依赖任何框架，没有构建步骤。

## 安装与引用

```bash
pnpm add @yue-ui/design-tokens
```

```js
import '@yue-ui/design-tokens/index.css'
```

```css
/* 或者从 CSS 引用 */
@import '@yue-ui/design-tokens/index.css';
```

## 入口

| 入口 | 文件 | 内容 |
| --- | --- | --- |
| `@yue-ui/design-tokens`（即 `./index.css`） | `src/index.css` | 层顺序声明 + 三个 Token 层（`primitives/`、`semantics/`、`component-tokens/`）。**这是唯一需要安装的入口。** |
| `@yue-ui/design-tokens/component-tokens/*.css` | `src/component-tokens/*.css` | 按组件命名空间拆分的 Component Token 声明（`layer(components)`），便于单独审计或按需读取；它们已被 `index.css` 引入，单独安装不会带来新东西 |
| `@yue-ui/design-tokens/implementations.css` | `src/implementations.css` | **可选**的原型期选择器归档（`.btn` / `.field` / `.list-row` 等）。不被 `index.css` 引用，只有显式安装才生效 |

`index.css` 是唯一的发布链路；另外两个入口是给审计、对照与迁移评审用的，名字必须与内容一致：
`component-tokens/*.css` 里只有 token 声明，`implementations.css` 里只有选择器。

（旧的 `./components.css` 导出已删除：它叫 token 文件却指向原型实现层的入口，是名实背离。）

**加载顺序是契约的一部分。** `index.css` 声明了

```css
@layer primitives, semantics, components, implementations, demo;
```

所以它必须先于任何组件样式加载。`component-tokens/*.css`（以及 `@yue-ui/vue/style.css`）
自身不再声明层顺序，否则可能在 `primitives` 之前创建 `implementations`，
把级联顺序反过来。

## Token 只有一处声明

Component Token 全部声明在 `src/component-tokens/` 里（每个组件命名空间一个文件，入口是 `_index.css`），其它文件只消费。这条规则由
`tools/lib/token-architecture.mjs` 强制（`corepack pnpm audit:tokens` 会跑）：

- 包内声明的每个 token 都必须能从 `index.css` 解析到——声明在不可达文件里就是失败；
- `@yue-ui/vue` 里每个 `var(--x)` 都必须有人声明（私有组合槽 `--_*` 除外）；
- 同一个 token 不允许在两个文件里各声明一次；
- `semantics/*.css` 不得引用 components/implementations 层独有的 token，`component-tokens/*.css`
  不得引用 implementations 层独有的 token；
- `component-tokens/*.css` 顶部的 `@yue-token-catalogue` 块必须覆盖自己文件里的每个 token，
  并写明它是否是可覆盖点（`public`）还是内部尺度（`internal`）。

这套门禁的由来：Tag 组件曾经在 `src/components/tag.css`（一个 `index.css` 从未引用的文件）里
声明自己的紧凑尺寸，而可达的那份是原型的控件尺度别名，于是 Tag 以 32px 胶囊渲染、
`shape="square"` 与 `shape="round"` 无法区分，`--tag-opacity-disabled` 与
`--tag-focus-ring-width` 干脆是未定义——而当时所有门禁都是绿的。

## 模式

```html
<html data-theme="dark" data-accent="neutral">
```

| 模式 | 触发方式 |
| --- | --- |
| 浅色 | `:root`（默认） |
| 深色 | `[data-theme=dark]`，同时设置 `color-scheme: dark` |
| Accent | `[data-accent=neutral]`；默认 azure 无需属性 |
| 强制颜色 | `@media (forced-colors: active)` |

## 资源

`assets/` 内含 6 个字体文件（HarmonyOS Sans SC ×4、FiraCode、TCloudNumber），
由 `src/primitives/typography.css` 中的 `@font-face` 通过 `../../assets/` 相对路径引用
（拆入子目录后多加一层，`verify:dist` 会核对构建产物里的字体 URL 是否存在）。
包内**不包含**图标字体：组件通过插槽接收图标，不绑定图标库。

> 已知取舍：字体约 17MB，会显著增大包的体积。做发布与 tarball 消费验证时会重新评估
> 是否拆成独立的可选子路径。

## 门禁

```bash
corepack pnpm audit:tokens          # 从仓库根目录
corepack pnpm -C packages/tokens audit   # 或只审计本包
```

对比度契约：迁移自原型的 32 组配对 + 包内新增的 23 组，浅色/深色各跑一遍（包目标 **110 项**，
原型 **64 项**），外加悬空引用、跨目标一致性与上面的架构检查。与原型的**有意分歧**
（Tag 的紧凑尺度与方角）逐条登记在 `tools/token-audit.pairs.mjs` 的 `PACKAGE_DIVERGENCES` 里，
每条带理由，且测试会断言「实际分歧集合 == 登记集合」——未登记的分歧失败，登记了却不再分歧也失败。
详见文档站的「Token 审计」页面。
