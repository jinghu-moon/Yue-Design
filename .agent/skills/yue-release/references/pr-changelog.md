# PR and changelog evidence

PR titles should use the repository's chosen Conventional Commit form. The body explains user and
developer-visible behavior, rationale, public API/Token/I18N changes, tests and known limits;
it does not merely enumerate files. UI changes include before/after screenshots or browser evidence.

Changelog entries are required only when the release process requests them. If written, update
all supported language files together, include component/API/token impact, and do not describe
internal refactors as user-visible features. Keep one coherent change per commit when practical.
